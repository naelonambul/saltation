# Shorten the Oracle lifecycle CI fixture

PR #20's Oracle job passed in 25 minutes 44 seconds. The local Oracle integration check took 19 minutes 3 seconds on the same tree. The existing lifecycle fixture waits for the full 420-second LIVE window and schedules its last live B/C cash-out at offset 370. The registered repository checks remain required. CI fixture pacing is independent of the approved production schedule.

## Order of work

1. In `generator/tests/stage6_lifecycle_harness.py`, reduce the fixture's LIVE window to 150 seconds. Retain the 60-second cutover lead and the three-second delayed acknowledgement-loss recovery. Only in the harness process, wrap the step expansion used by the scheduler and runner. For live B/C only, move the steps at offsets 290 and above 245 seconds earlier, leaving the first login and term opening in place. This preserves all action order, internal gaps after the opening dwell, same-second ATM session/cash pairs, prior operations, amounts, statuses, and KST dates. The last live B/C cash-out moves from offset 370 to 125, leaving 25 seconds to the 150-second deadline before the existing one-second episode start offset. Use a scoped context manager to patch the two imported step functions and restore them afterwards. Reject nonmonotonic or out-of-window live B/C steps. The harness is the only entry point to the timing override. Production code, CLI, defaults, eligibility rules, and the annual fixture schedule retain their existing behavior. Add focused offline checks in `generator/tests/test_stage6_lifecycle_pacing.py` covering both patched call sites and restoration, offsets, same-second ATM pairs, and unchanged other episodes. Verify with `scripts/dev/ci-py.sh lint` and `scripts/dev/ci-py.sh test`.
2. In `bank/tests/generator_lifecycle.rs`, expect the 150-second fixture duration and reconcile the explicit recorded end against the original Oracle switch timestamp plus that duration. Keep exact request IDs, authenticated lookup, monetary postings, dormant account activation, two separate D completions on three KST business dates each, zero annual D credit, exactly one generator mode switch and the separate idempotency probe. A controlled test still proves window expiry using the original start. Observe cutover and completion on real Oracle. Verify with `scripts/dev/it-oracle.sh generator-lifecycle`.
3. In `scripts/dev/it-oracle.sh` add elapsed wall-time diagnostics for the existing sequential integration targets, including the five generator proofs. Include distinct fixture preparation, waiting through the LIVE boundary and verifier-build/execution markers where available. Preserve exit codes, mandatory verifier execution, project lock and test isolation. Avoid a second Oracle instance or a change to cache trust. Save runtime samples under ignored `.evidence/`. Compare the baseline and candidate using the same runner and project serially, with the same Oracle image and workload. Require two consecutive successful lifecycle runs before opening the follow-up PR. For each attempt, record when preparation became ready relative to the cutover and validate each live B/C cash-out against the committed Oracle start and 150-second deadline, and report the measured margin after the last cash-out. Retain failed attempts and launch timings. A failed candidate attempt must be diagnosed and corrected before accepting two consecutive successes. Report total observed wall time and the 270-second reduction in scheduled LIVE duration separately. Treat variation from machine load or cache state as uncertainty. Finish with `python3 scripts/repo.py verify --change oracle-ci-lifecycle-speed --full` and one PR under the agent identity. Confirm the required checks and total Oracle job duration on the ARM64 CI runner separately. If the shortened run fails or lacks headroom on that runner, diagnose the failure and revalidate a larger fixture window instead of retrying until green. Step timings remain in runner-local evidence when CI logs do not expose them.

To roll back, restore the prior harness constants and Rust verifier duration, and remove the harness wrapper and its pacing tests together. This change leaves the existing validation routes and production timing intact.
